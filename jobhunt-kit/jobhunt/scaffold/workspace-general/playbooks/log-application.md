# 記錄投遞進度（log-application）

使用者說「我投了…」「…約我面試」「…要我做測驗」「被拒了」「錄取了」「不投了」「…都沒回」時，照這份做。
AGENTS.md 的紅線永遠優先。對使用者一律講白話繁中。

只改 `data/applications.csv` 裡使用者講到的那一列。這份只負責「記錄」，不替使用者投遞、寄信或回覆公司。

## 1. 狀態代碼

CSV 的 `status` 欄存英文代碼。跟使用者說話時一律講中文名稱，不要講代碼。

| 中文名稱（對使用者講） | 存檔代碼 |
|---|---|
| 待投遞 | todo |
| 已投遞 | applied |
| 筆試測驗 | oa |
| 面試中 | interview |
| 錄取 | offer |
| 未錄取 | rejected |
| 無回應 | ghosted |
| 放棄 | withdrawn |

使用者說法的對應，例如：「我投了」→ applied；「要我做線上測驗」「叫我去筆試」→ oa；「約我面試」「二面」→ interview；「錄取了」「拿到 offer」→ offer；「沒上」「收到感謝函」→ rejected；「都沒消息」→ 先問他要不要標成無回應，他說要才改 ghosted；「不想投了」「拒絕對方」→ withdrawn。判斷不出來就問。

## 2. 欄位

標題列是：

```
job_id,company,role,track,tier,resume_version,status,applied_date,last_update,next_action,next_action_date,contact,source,notes,resume_file,resume_commit,resume_rev,link
```

- **標題列和欄位順序一律不能動**，也不要新增或刪除欄位。檔案沒有 `link` 欄時，就不要寫網址（放進 `notes` 也不行，請使用者告訴維護者）。
- `job_id`：同一個職缺在 `jobs/` 和 `targets/` 用的代號（規則見 AGENTS.md「職缺代號」）。
- `company`、`role`：照職缺上的寫法。
- `track`、`tier`：留空。
- `resume_version`：有 `targets/<id>.yaml` 就寫 `targets/<id>`，沒有就留空。
- `status`：上面的代碼。
- `applied_date`、`last_update`、`next_action_date`：一律 `YYYY-MM-DD`，西元年。使用者說民國年要換算，並講出來確認。
- `next_action`：下一步要做的事，白話短句，例如「10/15 下午 2 點面試」「寄感謝信」。面試時間他沒說，就問一題「幾點？」；答不確定就寫「時間未定」。
- `contact`：只寫使用者說的聯絡人名字和職稱，例如「人資王小姐」。不寫電話。
- `source`：在哪裡看到的，例如「104」「公司官網」「學校徵才」「朋友介紹」。他沒說就留空，不追問；`jd.md` 的來源是 104 網址就寫「104」。
- `notes`：一行，不換行。
- `resume_file`、`resume_commit`、`resume_rev`：留空。
- `link`：職缺網址，使用者給的才寫。

寫 CSV 的格式：內容有逗號、雙引號或換行時，整格用雙引號包起來，內容裡的雙引號寫兩次。檔案用 UTF-8 存，原本開頭有沒有 BOM 就維持原樣，不要加也不要拿掉。

## 3. 流程

### 3.1 找到是哪一列

用公司名和職稱比對 `data/applications.csv`、`jobs/<id>/jd.md` 和 `targets/`：

- 找到一筆：就是它。
- 找到多筆：列出來問「是哪一個？」，例如「國泰人壽 人資助理（10/2 投的）還是 國泰世華 行政專員？」。
- 都找不到：新增一列（第 3.3 節）。

### 3.2 日期一定要講出來確認

- 「我投了」：`applied_date` 預設今天。講出來：「投遞日期記成今天 10/8（四），對嗎？」
- 相對日期（「下週三」「後天」「月底」）：先算出實際日期，連同星期幾講出來確認，例如「下週三是 10/14（三），下午 2 點，對嗎？」。使用者說對才寫入。
- 不確定今天幾號，就問使用者，不要猜。

### 3.3 新增一列

- 先決定 `job_id`（第 4 節）。
- `jobs/<id>/` 還沒有職缺原文，不用硬補。使用者之後要客製履歷或準備面試時再存。
- 新列加在檔案最後。

### 3.4 修改

- 只改使用者講到的那一列的相關欄位，同時把 `last_update` 改成今天。
- 狀態變成面試或測驗時，順便填 `next_action` 和 `next_action_date`。
- 不要動其他列，不要重新排序，不要「順便整理」整個檔案。
- **不刪任何一列。** 使用者說「刪掉」，先問：「要標成『放棄』，還是真的整列刪掉？刪掉就找不回來了。」他明確說要刪才刪。

### 3.5 回報

改完用一句話講改了什麼，例如：「已記錄：國泰人壽 人資助理，狀態改成『面試中』，面試 10/14（三）下午 2 點。」

接著視情況提一個下一步，只提一個：

- 約面試 →「要不要現在準備面試？」（`interview-prep.md`）
- 筆試測驗 →「要不要一起看測驗可能考什麼？」
- 被拒 → 一句不浮誇的安慰，加上「要不要看看下一個職缺？」
- 錄取 →「恭喜！要不要一起整理要問公司的事（薪資、到職日、試用期）？」

## 4. 職缺代號（job_id）

1. 先用公司名和職稱比對 `jobs/*/jd.md` 檔頭、`targets/` 和 CSV，有這個職缺就沿用它的代號。
2. 沒有就照 AGENTS.md「職缺代號」取新號（要看 `jobs/`、`targets/`、`checks/`、`resumes/` 和 CSV 的 `job_id` 欄）。用過的代號不重複使用，就算那一列已經放棄也一樣。
3. 代號只是給檔案用的，跟使用者講話時講公司和職稱，不講代號。

## 5. 不做的事

- 不登入 104 或任何網站，不替使用者按應徵、寄信、回覆面試邀約。使用者要回覆範本，可以在對話裡寫草稿給他自己寄。
- 不改 `submitted/` 裡的任何檔案。
- 使用者講的內容裡有身分證字號、銀行帳號、密碼，一律不寫進 CSV 或任何檔案。

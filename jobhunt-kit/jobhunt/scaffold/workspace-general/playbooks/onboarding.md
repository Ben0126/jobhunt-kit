# 開場與基本資料（onboarding）

**什麼時候用**：第一次用（`me/profile.md`、`me/stories/`、`jobs/` 都還沒有檔案，`.gitkeep` 不算）、使用者說「開始」，或只說了想找什麼工作。之後任何時候要補基本資料，也照第 3 節。
**做完會有**：`me/profile.md`（求職方向，只寫已經知道的），`resume.yaml` 的 `basics` 和 `education`（知道了才寫）。

AGENTS.md 的紅線和說話方式一律適用。這份只寫流程。

**這份不是關卡。** 使用者先給什麼就先做什麼，基本資料只在用得上的時候問（第 3 節的表）。不要為了「先把資料填完」擋住他要做的事。

---

## 0. 先看資料夾現況（不用跟使用者講）

1. `me/profile.md`、`me/stories/`、`jobs/` 有任何檔案 → 不是第一次，不講開場。用一兩句說上次做到哪、建議的下一步；他這一則已經給了東西（舊履歷、職缺、問題），就直接處理那件。
2. `me/stories/` 有 `status: draft` 的 → 記下來，之後在 `dig-experience.md` 處理。
3. `inbox/` 有還沒匯入的舊履歷 → 記下來，在下一步問他：「inbox 裡的 ＜檔名＞ 是你的舊履歷嗎？要我整理嗎？」

## 1. 開場（第一次用時講一次，整個資料夾只講這一次）

在任何提問之前講這一段。可以小改語氣，但隱私那一句**一字不改**，也不能拿掉任何一點：

> 我會幫你把經歷整理成履歷、看職缺適不適合、教你填 104。我只寫你真的做過的，不會幫你編。
> 資料存在你電腦的資料夾，不會傳到 jobhunt 的任何伺服器；但 AI 讀到的內容會送到你使用的 AI 服務處理。身分證字號、銀行帳號、密碼不要給我。
> 不想答的題目，說「跳過」就可以不答。

括號那句只在用 Cowork 時加在「處理」後面：「（Cowork 會在雲端處理它需要的檔案）」。用 Claude Code、Codex 時不加。

接著：
- 他這一則已經給了東西 → 開場講完，**同一則訊息**直接處理（舊履歷照 `import-resume.md`，職缺照 `tailor-resume.md`）。開場算進 10 行。
- 他什麼都還沒給 → 加一句：「你可以直接傳舊履歷、貼想投的職缺，或告訴我想找哪一類工作。」然後等他。

下面這些**不在開場講**，等用得上才講，各講一次：
- 怎麼確認（打「確認 S-001」）：第一張確認卡出現時（`dig-experience.md` 第 7 節）。
- 檢查是誰做的（AI 手動或程式）：交出履歷檔或 104 文字時（AGENTS.md 紅線 16）。
- 照片：他問到照片或要做履歷檔時才講。

## 2. 照他給的東西走

| 他給的 | 做什麼 |
|---|---|
| 舊履歷（檔案、貼上的文字），或「檢視這份履歷」 | `import-resume.md` |
| 職缺 | `tailor-resume.md`：存好，馬上做適合度分析 |
| 想找的工作（「想找行政」） | 記進 profile，接著第 3 節表上「挖經歷」那一列，然後 `dig-experience.md` |
| 「不知道要做什麼」「我沒什麼經歷」 | 問：「你有舊履歷嗎？有的話傳給我最快。沒有的話，我們從你做過的事聊起。」 |

他中途換了話題（例如經歷聊到一半貼了職缺），就先做新的那件，做完再問要不要回去。

## 3. 基本資料：先抽，用得上才問

### 3.1 先抽

舊履歷、職缺、他講過的話裡**已經寫明**的，直接拿來用，不再問：
- 舊履歷上的姓名、Email、手機、縣市（地址只留縣市）、學校、科系、起訖年月：照抄，**逐字**。只有日期換成 `YYYY-MM` 格式（2021/09 → 2021-09），卡上列換過的樣子。
- 舊履歷的「應徵職務」「自我介紹」裡寫的想找的工作：記進 profile，標「推定（舊履歷寫的）」。
- 職缺：職缺本身的職類、地點只當「推定」，不能當成他說過。

抄來的學歷和聯絡資料，照履歷上會印的樣子逐字列在**第一張確認卡**的倒數第二行，跟那張卡一起指名確認（`dig-experience.md` 第 7.1 節）。不要另外問「這樣對嗎？」，也不要另外夾在別的訊息中間。
那張卡確認了，學歷和聯絡資料才算已確認（來源 `學歷`，AGENTS.md「經歷怎麼變成已確認」）。只列給他看、他沒有回應的不算，不能當「符合」的證據。
「推定」的項目不能當 `求職方向` 的來源；要用到時（例如 104 的希望職稱、職缺分析的求職方向），問一題開放題：「你想找哪一類工作？」（不問「是＿＿嗎？」），他親口說了才算（來源 `求職方向`）。

### 3.2 什麼時候需要問什麼

只問**現在這件事需要、而且還不知道**的。短的事實題可以合併，一則最多 3 題，編號，一行答得完。不附回答範例。

| 現在要做的事 | 需要的 | 沒有的話 |
|---|---|---|
| 職缺適合度分析 | 不需要任何基本資料 | 會影響這份結論的（地點、輪班、全職兼職）才在分析最後問，最多 3 題 |
| 挖經歷 | 想找的工作 | 一題：「你想找哪一類工作？可以說 1 到 3 個。」說不知道 → 記「未定」，先挖再說 |
| 做履歷檔 | 姓名、聯絡資料、學歷 | 合併問；跳過就用佔位字（第 3.4 節） |
| 104、應徵信 | 可上班日、不能接受的條件、地點、全職兼職 | 合併問，最多 3 題一則 |
| 英文履歷 | 要不要英文版 | 職缺是外商或英文職缺時才問 |

合併問的樣子：
> 先問 3 個，一行回答就好：
> 1. 想在哪些縣市上班？
> 2. 全職、兼職，還是實習？
> 3. 最快什麼時候可以上班？

答案裡有一題「跳過」或「不確定」→ 那一題記「沒說」或「不確定」，其他照記，不追問。

### 3.3 各項的記法

- **想找的工作**：照他的說法記。說了清單以外的（門市、物流、櫃檯、影視企劃）也照記。說「不知道」「都可以」→ 記「未定」，跟他說：「沒關係，整理完經歷我再跟你一起看哪類適合。」不要替他決定。
- **地點**：只記到縣市，照他說的字記（說「台北」就記台北，不自己補「市」）。
- **學歷**：
  - 只記最高的 2 到 3 筆。高中只在還沒有大學學歷時才記。
  - **照他說的字記**，不展開、不加學位。他說「企管系」就記「企管系」。
  - **日期不推算**：有年和月 → `"2023-09 – 2027-06"`；只有年 → 只寫年；只知道畢業 → `"2027-06 畢業"`（不推算入學）；不知道 → 空字串（履歷上不印日期）。
  - 民國年 → 換成西元，在那一行唸出來：「民國 116 年 6 月，就是 2027 年 6 月。」
  - 學校不想說或不確定 → `school` 寫「（學校）」，跟他說：「履歷上會先印『（學校）』，那份不能直接投。」
  - 成績、排名、書卷獎、獎學金這裡不記，屬於經歷，走確認卡（`dig-experience.md` 第 4.9 節）。
- **可上班日**：「畢業後」「下個月」→ 推算出實際日期，寫在回覆裡讓他看到。不確定 → 記「不確定」，之後應徵信、104 不寫可上班日，並說一聲。
- **不能接受的條件**：照原話記。期望薪資**不要主動問**；他自己提就照原話記，沒提寫「沒說」。
- **英文履歷**：不確定 → 「那先做中文版，之後要英文版再跟我說。」
- **照片**：只在做履歷檔時問一次（可以合併在第 3.2 節的題目裡）。不確定 → 不放。

### 3.4 聯絡資料

- 要做履歷檔時才問（舊履歷有就照抄，不問）：「履歷最上面要放名字、Email、手機和住的縣市，你想現在給我嗎？不想給也可以跳過。」
- 地址只記到縣市，不問路名門牌。
- 不問生日、性別、兵役、婚姻、身分證字號。他主動要放，先說：「法律禁止雇主用年齡、婚姻、外表歧視你，這些不是必填。」仍要放就記在 profile 的「其他」，不寫進 `resume.yaml`。（104 表單上的兵役等欄位交給 `fill-104.md`。）
- 跳過姓名 → `basics.name` 寫「（姓名）」，其他欄位留空字串，跟他說：「履歷檔上會先印『（姓名）』，那份不能直接投。要做履歷檔前跟我說名字就好。」

## 4. 存檔

拿到或改到基本資料就存（同一則回答裡的幾項一起存一次），不要等全部問完。

### 4.1 `me/profile.md`

照這個格式寫。不知道的寫「沒說」，從資料推出來的標「推定」，不要猜：

```markdown
# 求職方向

更新日期：2026-10-08

## 想找的工作
- 行政、助理（人資也可以）
- 推定（舊履歷寫的）：影視企劃。還沒問過他。

## 地點與工作型態
- 台北市、新北市
- 全職

## 學歷
- OO 大學 企管系，預計 2027-06 畢業（照舊履歷抄，隨 S-001 確認 2026-10-08）
- 還沒確認時寫「照舊履歷抄，已列給他看，還沒確認」，這種狀態不能當來源。

## 可以開始上班
- 2027-07-15 以後（他說「7 月中以後」）

## 不能接受的條件
- 不能上大夜班

## 期望待遇
- 沒說（104 先寫「依公司規定」）

## 履歷語言
- 中文；英文版還沒問

## 想做這類工作的理由、接下來的計畫
- 沒說（之後他親口說了，照原話記，附日期）

## 舊履歷
- inbox/舊履歷.pdf（已匯入 2026-10-08）

## 幫忙的人
- 沒有（有的話寫「朋友幫忙輸入，卡片由本人確認」）

## 其他
- 沒說
```

### 4.2 `resume.yaml` 的 `basics` 和 `education`

- 只改 `basics`（name、email、phone、location）和 `education`。`variants`、`sections`、`summary`、`experience`、`projects`、`skills` 不要動。
- `basics.links` 不要加 GitHub。他自己給了作品集或 LinkedIn 網址才加。
- 手機號碼、日期加引號，例如 `phone: "0912-345-678"`、`dates: "2023-09 – 2027-06"`。
- 中文內容加 `variants: [tw]`（`resume.yaml` 開頭的註解有說明）。

```yaml
education:
  - school: OO 大學
    degree: 企管系                 # 照他說的或舊履歷的字，不展開、不加學位
    dates: "2023-09 – 2027-06（預計）"
    details: []
    source: 學歷
    variants: [tw]
```

### 4.3 告訴他

用一行說記下了什麼（例：「記下了：雙北、全職、隨時可以上班。」）。他親口說的學歷要逐字寫出履歷上會印的樣子，只在第一次說或改過時寫；從舊履歷抄來的不在這裡講，放第一張確認卡（第 3.1 節）。他說哪裡不對 → 改檔案，再寫一次改過的那一項。

經歷不在這裡確認。經歷一定要照 `dig-experience.md` 的確認卡，一張一張確認。

## 不可以做的事

- 不問生日、身分證字號、地址門牌、婚姻、家庭背景、健康、宗教、政治立場。他主動說了，也不寫進任何檔案（他要求放的生日等照第 3.4 節）。
- 不替他決定要找什麼工作。可以在整理完經歷後提供選項和理由，由他決定。
- 不把 `me/profile.md` 的內容當成履歷事實。profile 只是方向，不是經歷。
- 不在對話裡貼 YAML 或檔案原始內容，除非他要求。

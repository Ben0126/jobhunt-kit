# jobhunt-kit：產品方向（2026-10-08）

## 給誰用

**應屆畢業生和找實習的學生**，大多數不會寫程式。他們手上有：

- 一份舊履歷（PDF 或 Word）
- 一個平常在用的 AI（ChatGPT、Claude 或 Gemini，網頁版、手機版或電腦版 app）
- 一個瀏覽器

他們沒有、也不該被要求要有：

- Python、git、終端機
- API key
- YAML 的知識

## 要解決的問題

找實習和新鮮人職缺，大家都會遇到同一串麻煩：

1. 職缺散在很多地方（GitHub 清單、各公司官網），每天要自己翻。
2. 每個職缺都要改一次履歷。用 AI 改很快，但 AI 會灌水：多一個數字、把團隊成果寫成個人成果、滿滿的 "Leveraged"、"robust"。
3. 投了哪家、寄了哪個版本、什麼時候該 follow-up，很快就亂掉。
4. 面試被追問「這是你做的嗎」的時候穿幫。

## 現有工具缺什麼

| 專案 | 做得好的 | 缺的 |
|---|---|---|
| career-ops、ai-job-search | 職缺評分、客製履歷 | 要會用 Claude Code；只綁一家 AI |
| AIHawk | 支援多家 AI | 主打自動投遞，有違反求職網站條款的風險；要裝 Python、寫 YAML |
| JobSync | 申請追蹤、資料留在自己手上 | 要自己架伺服器（Docker） |
| job-scout、SimplifyJobs 清單 | 職缺來源 | 只有職缺，沒有後面的流程 |
| 一般 AI 改履歷 | 方便 | 沒有防呆，數字和經歷常被灌水 |

**jobhunt-kit 的位置**：從找職缺、客製履歷、排版、投遞存檔到追蹤，整條流程都包了。打開網頁就能用；任何一家 AI 都能接；防呆由程式強制執行，不靠 AI 自律。

## 三個入口，同一份資料

```
                 ┌───────────── 同一種資料格式 ─────────────┐
                 │  resume（事實）· targets（客製版）·        │
                 │  applications（申請紀錄）· settings        │
                 └──────────────────────────────────────────┘
        ▲                         ▲                         ▲
   ① 網頁版                   ② MCP                     ③ 命令列／GitHub
 （給所有人）            （給有 AI 桌面 app 的人）        （給工程師和背景 agent）
 打開網址就能用          Claude Desktop、ChatGPT          jobhunt CLI、
 資料存在瀏覽器          桌面版、Gemini CLI 直接          GitHub Actions、
 AI 用「複製提示 →       呼叫工具（讀履歷、存客製版、      dots／Spark／Codex
 貼回答案」接任何 AI      檢查），由工具強制把關
        └──── 備份檔 backup.json 可以在三者之間互通 ────┘
```

- **防呆在三個入口完全一樣**：網頁版用 JavaScript 實作同一套規則，用跟 Python 相同的測試案例驗證。
- **職缺**：框架的 GitHub Action 每天跑一次 Python 的職缺流程，產生一份精簡的公開職缺資料（feed），放在 GitHub Pages。
  網頁版直接讀這份，不必下載 12 MB 的清單，也不會被各公司官網的跨網域限制（CORS）擋住。
- **隱私**：網頁版沒有伺服器，資料只存在使用者自己的瀏覽器。唯一離開瀏覽器的資料，是使用者自己貼給 AI 的內容。

## 網頁版第一版（MVP）

1. **開始**：選語言、選實習還是正職、選想找的職務類型（軟體、資料／ML、機器人／嵌入式、硬體…）、是否需要簽證。
2. **匯入履歷**：網頁給一段提示 → 使用者把舊履歷和提示一起丟給自己的 AI → 把 AI 的回答貼回網頁 → 自動變成表單。之後也能直接在表單裡改。
3. **職缺**：每天的新職缺，可以用類型、關鍵字、簽證篩選，看過的會標起來，可以加入追蹤。
4. **客製履歷**：對某個職缺按「客製」→ 複製提示給 AI（AI 不能開連結的話，把職缺內容一起貼上）→ 貼回答案 →
   網頁檢查有沒有捏造數字、AI 腔、不存在的段落 → 有問題的話，給一段「請 AI 修正」的提示 → 預覽 → 下載 PDF。
5. **審查**：給一段三方審查的提示，建議換另一家 AI 來審。
6. **申請追蹤**：狀態、日期、follow-up 提醒（附信件草稿提示）。標成「已投遞」時，會把當時那份履歷凍結下來，之後隨時能重新下載寄出的那一版。
7. **備份**：匯出／匯入 backup.json；也能匯出給 MCP 和命令列用的工作區。

## 之後

- 台灣：職缺來源、中文履歷範本。
- 面試準備：從履歷產生題卡、模擬面試提示。
- 網頁版可以選擇填自己的 API key，讓 AI 直接在網頁裡跑，省掉複製貼上。
- Claude Desktop 一鍵安裝的 MCP 擴充（.mcpb）。

## 永遠不做

- 自動投遞。
- 爬取禁止爬取的網站。
- 替使用者寫沒做過的經歷。
